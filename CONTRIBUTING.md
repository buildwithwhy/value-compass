# Contributing to Value Compass

This guide covers the two most common changes: adding to the dataset (makers,
funders, axis scores) and keeping the CI gates green. The dataset is the
product — everything else (compass, comparisons, API export, graph) renders
from it — so edits to `src/data/` are reviewed more strictly than UI code.

## Repository layout

```
src/data/
  makers.json        23 maker records + _meta (the scored directory)
  funders.json       35 funder records + _meta (capital network; joins by maker id)
  evidence.json      script-derived per-axis evidence verdicts — NEVER hand-edit
  methodology.md     scoring methodology
  rubric.md          the scoring rubric — read before scoring any axis
src/lib/
  types.ts           domain types (Tier, Confidence, AxisKey, Maker, Funder)
  schema.ts          pure validators backing the schema guard tests
  schema-waivers.ts  legacy data-debt ratchet (see "Waivers" below)
scripts/
  build-evidence.mjs regenerates evidence.json — the only writer of that file
  export-api.mjs     emits public/api/v1/ at build time
docs/
  RESEARCH_BATCH.md  completed research (basis for the five placeholder entries)
```

## The three rules that outrank everything else

1. **No score without a source.** An axis score must cite at least one source
   URL in its `sources[]`. If your research doesn't support a score, leave the
   axis `null` (or `'n/a'` for insufficient evidence) with a note explaining
   why — that is a complete, honest entry, not a failure.
2. **Never hand-edit `evidence.json`.** It is regenerated by
   `scripts/build-evidence.mjs` from `makers.json` and the eligibility logic in
   `src/lib/evidence.ts`. Hand edits are overwritten on the next build.
3. **The dataset's own metadata must not drift.** `_meta.count` must equal the
   actual record count — a drift-guard test fails the build otherwise. Update
   the count in the same commit that adds a record.

## Adding a maker

Append an object to the `makers` array in `src/data/makers.json` and bump
`_meta.count`. Required shape (see `src/lib/types.ts` → `Maker`):

| Field | Type | Rules |
|---|---|---|
| `id` | string | Join key used by funders' `makers_backed` / `owns_outright`. Keep it the company's common name, e.g. `"Google DeepMind"`. Never changes after publication. |
| `slug` | string | URL-safe route address, e.g. `"google-deepmind"`. Rules below. Never changes after publication. |
| `name` | string | Display name. |
| `tier` | string | One of `frontier`, `tool`, `frontier_and_funder`, `platform`. |
| `jurisdiction` | string | May be `"Not researched"` until researched — never an empty string. |
| `vc_independent` | string | Factual capital posture, e.g. `"VC-backed (hyperscaler-strategic)"`. |
| `products_models` | string[] | Products or models offered; empty only if genuinely none are documented. |
| `founders` | string[] | May be `[]` if research established nothing. |
| `structure` | string | Ownership/legal structure in one or two sentences. |
| `stated_values` | string | What the company itself claims. |
| `tension_hook` | string | The gap between stated values and practice — the honest tension, kept neutral. |
| `axes` | object | All five axis keys (`transparency`, `culture_esg`, `labour_integrity`, `wealth_dispersion`, `public_sharing`), each a full entry — see "Scoring an axis". |
| `capital_profile` | object | See the `CapitalProfile` type; include when funding structure is known. |

### Slug rules

- Lowercase letters, digits, and hyphens only: `/^[a-z0-9]+(?:-[a-z0-9]+)*$/`
  (`"Google DeepMind"` → `google-deepmind`; `"xAI"` → `xai`).
- Unique across all makers — slugs are route addresses (`/maker/<slug>`), so a
  duplicate breaks navigation.
- Immutable once published: routes, the API export, and external links all
  depend on it.
- No renaming a maker `id` either — funder records join on it.

## Scoring an axis

Read `docs/rubric.md` and the `scale`/`confidence` anchors in
`makers.json`'s `_meta` first. Each axis entry:

```json
"transparency": {
  "score": 2,
  "confidence": "A",
  "note": "Why this score, in one or two sentences",
  "sources": ["https://primary-source.example/report"]
}
```

- **`score`** — integer 0–4. 0 = worst-in-class, 2 = industry-typical,
  4 = best-in-class/binding. Higher always means more pro-social (see the
  `_meta.polarity` note). `null` = not scored (with a reason),
  `'n/a'` = insufficient evidence — never score a 0 to mean "unknown".
- **`confidence`** — one of:
  - `A` — strong / externally validated (e.g. a Stanford FMTI score exists)
  - `B` — moderate / some primary disclosure or credible reporting
  - `C` — thin / inferred / single-source
- **`note`** — non-empty, states the basis. An unscored entry (`null`/`'n/a'`)
  must start with **`"Not scored."`** followed by the reason, e.g.:
  `"Not scored. The batch research (docs/RESEARCH_BATCH.md, 2026-09-27) established no finding for this maker on this axis."`
- **`sources`** — for a scored entry, at least one source URL. Empty `sources`
  is only valid on an unscored entry. Every source must be a real URL — do not
  invent one to satisfy the guard; that's worse than an unscored axis.

The schema guard tests enforce every rule in this section at CI time, including
on the corpus as a whole — so a new score without a source fails `npm test`
even if it would otherwise have gone unnoticed.

## Adding a funder

Append an object to the `funders` array in `src/data/funders.json`, bump
`_meta.count`, and give it:

- `id` — same slug rules as maker slugs; it's the funder's route address
  (`/funder/<id>`) and join key.
- `name`, `parent_type` — non-empty strings.
- `makers_backed` / `owns_outright` — arrays of **maker `id`s** (join on id,
  never display name). Every reference must resolve to a real maker; the
  join-integrity guard fails on a dangling edge.

## Waivers: the legacy-debt ratchet

`src/lib/schema-waivers.ts` lists pre-existing violations of the rules above —
legacy makers scored before the evidence discipline existed (~39 scored-but-
unsourced axis entries) and three empty fields awaiting sourced research. This
is a **one-way ratchet**:

- A violation **not** in the list fails the build.
- A waiver whose debt has been fixed also fails the build — delete the waiver
  line in the same PR that adds the sources or fills the field.
- Adding a waiver line requires reviewer sign-off: it means knowingly shipping
  another rule violation.

If your honest, sourced change makes the ratchet fail because you *fixed*
waived debt — remove the line, that's the ratchet working.

## Running tests and build

```bash
npm install        # once
npm run test       # vitest — schema guards, drift guards, eligibility, etc.
npm run build      # typecheck (tsc -b) + export-api + vite build + emit-routes
npm run test:watch # watch mode while iterating
```

CI runs typecheck, tests, and build on every PR; a red check blocks merge. If
you changed data, also run `npm run build` locally — the export step validates
joins and emits `public/api/v1/`, and its output should be byte-identical
across consecutive runs (deterministic build).

## Before you open a PR

- [ ] `npm run test` green locally.
- [ ] `npm run build` green locally; re-running it changes no bytes.
- [ ] `_meta.count` updated in every data file you appended to.
- [ ] New slugs/ids unique and URL-safe; no existing id or slug renamed.
- [ ] Every new score has a non-empty note and at least one real source URL,
      or the axis is `null`/`'n/a'` with a `"Not scored. …"` note.
- [ ] Funder references join on maker `id`s that exist.
- [ ] If you retired waived debt: the matching line removed from
      `src/lib/schema-waivers.ts`.
